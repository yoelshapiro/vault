Pre-Intervention Trajectory Correction

When a safety driver disengages the autonomous vehicle, the seconds just before the takeover capture the model heading toward a mistake. This data-pipeline augmentation rewrites those training labels — the path and the speed — so the policy learns the expert's correction earlier and smoother, instead of the behaviour that caused the disengagement.

wayve/ai/zoo/augmentations/pre_intervention.py branch · boris/pudo_generic_materialization .augment_vehicle_preintervention

1 The big picture

A safety-driver disengagement is a free supervision signal: the human only grabs the controls because the car was about to do the wrong thing. The recorded trajectory after the takeover is the expert's fix. This augmentor reaches backward in time and rewrites the pre-takeover labels so they smoothly flow into that fix.

What it reads

Real on-road AV logs: the automation_active flag, vehicle speed, the geometric path, and the policy targets (policy_*).

What it writes

New policy_speed / curvature / pose / waypoints + a re-fitted path, keeping the originals under original_* keys.

What it teaches

Begin braking / accelerating / steering before the point where the human had to intervene — anticipation, not reaction.

The one-sentence mental model

Draw a smooth clothoid arc from where the car is now to a rejoin point 2·d + 3 metres down the recorded (expert) path, and re-time the speed with a linear ramp that reaches the expert's eventual speed by the moment of intervention — then resample everything into the policy's target slots.

2 Where the data comes from

The augmentor is a functional_datapipe("augment_vehicle_preintervention") spliced into the data pipeline. Each item flowing through is a (table, data) pair: table is the raw per-frame run log (numpy arrays), data holds the model's labels for the sampled frame.

The trigger: a disengagement = automation turning OFF

Every frame carries automation_active. An intervention is the index where it flips True → False. That's the safety-driver takeover.

def get_intervention_offsets(automation_active):
    # index where automation_active goes True -> False (a disengagement)
    a = automation_active.astype(np.float32)
    (intervention_start,) = np.where(np.diff(a) < 0)
    return intervention_start + 1

Key insight — the path already contains the expert fix

path_pose is the recorded future trajectory. After the disengagement, those points are what the human actually drove. So the "rejoin target" downstream already encodes the expert outcome — the augmentation only needs to build a smooth, physically-consistent label that reaches it.

3 How the correction works

The engine is correct_trajectory() pre_intervention.py:257. It rewrites geometry and timing in lock-step, then resamples poses along the new path. Here is the whole thing as readable pseudocode:

def correct_trajectory(path, path_curvature, intervention_index, speed, ...):
    # --- A. how far does the car travel before the human takes over? ---
    original_distances = cumdist_from_speed(speed, time_step)   # trapezoid of |speed|
    distance_to_intervention = original_distances[intervention_index]

    # --- B. choose a rejoin point on the recorded (expert) path ---
    distance_to_correction_end = 2 * distance_to_intervention + 3   # metres
    correction_end_index = round(distance_to_correction_end / path_step)

    # --- C. don't iron out a genuine stop-and-reverse cusp (parking!) ---
    correction_end_index, clamped, first_opposite = _clamp_at_direction_change(...)

    # --- D. re-fit the path as a clothoid from now -> rejoin point ---
    if interpolate_path:
        is_reverse = _is_reverse_from_speed(speed)        # sign of first non-zero speed
        _validate_clothoid_direction(...)                 # geometry must agree with speed
        corrected_path, corrected_curv, valid = correct_path(
            path, path_curvature, start=0, end=correction_end_index,
            method="clothoid", reverse=is_reverse)

    # --- E. zero speed past a clamped direction change (decelerate to the cusp) ---
    if clamped:
        speed_for_correction = speed.copy(); speed_for_correction[first_opposite:] = 0.0

    # --- F. re-shape the speed: linear ramp v0 -> v2 ---
    new_speed, _, _, acc_pre = correct_speed(speed_for_correction,
                                             intervention_offset=intervention_index,
                                             offset=speed_offset)
    acc_pre /= time_step                                  # delta-v/step -> m/s^2
    acc_int = compute_window_accel(speed, intervention_index, window_s=1.0)

    # --- G. crop, then fit ego-poses to the new speed along the new path ---
    new_distances = cumdist_from_speed(new_speed, time_step)
    new_poses, new_curvature = interpolate_pose_and_curvature_along_path(
        new_distances, corrected_path, corrected_curv)

    # --- H. safety gate: slow-down intervention must not pair with speed-up heuristic ---
    validate_pre_intervention_accelerations(intervention_what, acc_int, acc_pre)
    return corrected_path, corrected_curv, valid, new_poses, new_speed, new_curvature, new_time_deltas

The speed law — correct_speed

A single linear ramp replaces the pre-intervention speed. With t1 = ix + offset and t2 = 2·ix + offset:

t0, t1, t2 = 0, ix + offset, 2*ix + offset
v0, v2 = speed[t0], speed[t2]        # now, and the future/expert speed
a01 = (v2 - v0) / (t1 - t0)          # constant accel
v01 = v0 + a01 * arange(t1)          # the ramp
v = concat([v01, speed[t2:]])        # ramp, then original tail
intervention.py:251intervention.py:251

Invariants (proven by test_speed_correction): new_speed[0] == speed[0] and new_speed[t1] == speed[t2], and the tail from t2 on is copied verbatim. So the car is told to start matching the expert's eventual speed now.

The path law — correct_path

A clothoid (curvature linear in arc-length — the curve your steering wheel traces at constant turn rate) is fit between two boundary poses:

# boundary poses: start = pose[0], end = pose[correction_end]
fit_theta0 = theta0 + pi if reverse else theta0
fit_theta1 = theta1 + pi if reverse else theta1
clothoid = Clothoid.G1Hermite(x0,y0,fit_theta0, x1,y1,fit_theta1)
# sample evenly along arc-length, negate curvature/heading if reverse
# then continue original spacing past the rejoin point
trajectory.py:72 — also supports bezier / straighttrajectory.py:72

The first start points are copied unchanged, the boundary poses are matched exactly, and waypoints stay ≈0.25 m apart (proven by test_correct_path). One smooth arc replaces the late, jerky human takeover.

Why 2·d + 3?

The rejoin distance scales with how far the car travels before the takeover (d), giving the clothoid room to ease in proportionally, plus a +3 m floor so even a near-stationary car has a sane arc. The corrected path must merge back to the recorded path by this point — beyond it, the label is the recorded expert trajectory.

The acceleration safety gate

Some interventions are unambiguous slow-downs (braking for a red light). If the heuristic instead produced an acceleration, the label would be nonsense — so the sample is dropped.

def classify_acceleration(a, threshold=0.2):     # -> -1 / 0 / +1
    if a < -threshold: return -1                  # decelerating
    if a <= threshold: return 0                   # roughly steady
    return 1                                       # accelerating

def validate_pre_intervention_accelerations(what, acc_intervention, acc_pre):
    if what not in ["failed_to_remain_stopped", "failed_to_slow"]:
        return                                     # gate only applies to slow-downs
    if classify_acceleration(acc_intervention) == -1 and classify_acceleration(acc_pre) == 1:
        raise BadPreInterventionException("Intervention slowing down but heuristic speeding up.")

4 Code walkthrough — augment()

The per-sample entry point. Read top-to-bottom, it is exactly the gate → correct → write flow.

def augment(self, data, table):
    # 0. bail if a mitigation is already requested
    mitigation = data.get(MITIGATION_REQUEST)
    if mitigation is not None and int(mitigation[0]) != NO_MITIGATION:
        return data

    origin = self.get_origin(table)
    time_step = self.get_time_step(table)
    speed_offset = round(self.speed_offset_sec / time_step)
    max_pre_offset = round(self.max_pre_intervention_offset_sec / time_step)

    # 1. limit search so we don't pick up a distant future disengagement
    search_limit = origin + max_pre_offset + round(1.0 / time_step)
    automation_active = table[AUTOMATION_ACTIVE][:search_limit]

    # 2. is this actually a pre-intervention frame?
    pre_ca_candidate = automation_active[origin] and (
        time_until_intervention_sec[origin] < self.safeguard_clean_av_offset_sec)
    if not pre_ca_candidate:
        return data

    intervention_what = first_nonempty(table.get("inferred__intervention__what", "")) or "not in binaries"
    intervention_offsets = get_intervention_offsets(automation_active)

    # 3. validate pose / intervention / required keys / full path
    self.validate_vehicle_pose(data)
    self.validate_intervention(origin, max_pre_offset, intervention_offsets)
    self.check_data_keys(data)
    if not np.all(data[PATH_VALID]):
        raise BadPreInterventionException("...requires a full-length path.")

    speed = table[speed_kmh][origin:] / 3.6           # m/s, from the current frame on

    # 4. the actual correction
    (results[PATH_POSE], results[PATH_CURVATURE], results[PATH_VALID],
     future_pose, future_speed, future_curvature, future_time_delta) = correct_trajectory(
        path=data[PATH_POSE], path_curvature=data[PATH_CURVATURE], speed=speed,
        time_step=time_step, intervention_index=intervention_offsets[0] - origin,
        speed_offset=speed_offset, interpolate_path=self.interpolate_path,
        path_length=self.path_length, path_step=self.path_step,
        intervention_what=intervention_what)

    # 5. resample to the policy's query times & store labels (keeps original_* copies)
    data = self.add_results_to_data(data, future_speed, future_pose, future_curvature,
                                    future_time_delta, results,
                                    allow_future_reinterpolation=self.allow_future_reinterpolation)
    return data

How labels are written back — add_results_to_data

The corrected future series are at future_time_delta spacing. The policy wants values at its own policy_time_delta query times, so they're either looked up (tolerance 0.01 s) or re-interpolated.

def add_results_to_data(data, future_speed, future_pose, future_curvature, future_time_delta, results, ...):
    time_delta = data[POLICY_TIME_DELTA]
    if np.any(time_delta < -1e-3):
        raise RuntimeError("policy has negative time deltas — past data not supported")

    if allow_future_reinterpolation and needs_interpolation:
        results[POLICY_SPEED]     = np.interp(time_delta, future_time_delta, future_speed)
        results[POLICY_CURVATURE] = np.interp(time_delta, future_time_delta, future_curvature)
        results[POLICY_POSE]      = interpolate_poses_and_curvature(time_delta, future_time_delta, future_pose)
    else:
        results[POLICY_SPEED]     = extract(future_speed,     k=future_time_delta, q=time_delta, atol=0.01)
        results[POLICY_CURVATURE] = extract(future_curvature, k=future_time_delta, q=time_delta, atol=0.01)
        results[POLICY_POSE]      = extract(future_pose,      k=future_time_delta, q=time_delta, atol=0.01)

    results[POLICY_WAYPOINTS] = results[POLICY_POSE][:, :2, -1].copy()
    data.update({f"original_{k}": data[k] for k in results})   # keep originals!
    data.update(results)
    data["is_pre_intervention_corrected"] = np.array(True)
    return data

5 Edge cases & safety logic

This is where most of the file's complexity lives — reverse driving and parking manoeuvres break naïve assumptions. Each case below is backed by a test in test_pre_intervention.py.

▶ Reverse & mixed-direction driving |speed| for distance

Speed can be negative (reverse). Distances are integrated on the absolute speed so they stay monotonically increasing, while the signed speed is preserved in the output so the policy still knows it's reversing.

def cumdist_from_speed(speed, dt):
    avg = 0.5 * (speed[1:] + speed[:-1])
    return cumsum(abs(avg) * dt)   # abs -> distance, not signed displacement

Tests: test_correct_trajectory_with_negative_speed (all-reverse stays ≤0), test_correct_trajectory_with_mixed_speeds (distance still monotone), test_reverse_only_correct_trajectory.

▶ Direction-change clamp — don't iron out a stop-and-reverse cusp parking

If the car goes forward then reverses (or vice-versa) after the intervention, a clothoid spanning that cusp would smooth away a real, intended inflection. The clamp shortens the rejoin point to the cusp and forces the speed to decelerate to zero there.

def _clamp_at_direction_change(speed, intervention_index, correction_end_index, original_distances, path_step):
    nonzero = np.nonzero(speed)[0]
    initial_sign = np.sign(speed[nonzero[0]])                 # NB: first *non-zero*, not speed[0]
    opposite = np.sign(speed[intervention_index:]) == -initial_sign
    if not np.any(opposite):
        return correction_end_index, False, None              # no reversal -> no clamp
    first_opposite_idx = intervention_index + argmax(opposite)
    max_path_idx = round(original_distances[first_opposite_idx] / path_step)
    if max_path_idx < correction_end_index:
        return max(max_path_idx, 1), True, first_opposite_idx  # clamp + zero speed past cusp

▶ Clothoid-vs-speed direction consistency check drop on mismatch

The travel direction is inferred two ways: from the speed sign and from the clothoid geometry (which of forward/reverse tangents gives the shorter arc). If they disagree, the data is inconsistent and the sample is dropped.

def _validate_clothoid_direction(path, correction_end_index, is_reverse, speed):
    clothoid_fwd = Clothoid.G1Hermite(x0,y0,theta0,        x1,y1,theta1)
    clothoid_rev = Clothoid.G1Hermite(x0,y0,theta0 + pi,   x1,y1,theta1 + pi)
    geometry_says_reverse = clothoid_rev.length < clothoid_fwd.length
    if geometry_says_reverse != is_reverse:
        raise BadPreInterventionException("Clothoid direction disagrees with speed sign.")

▶ Zero speed (fully stationary) stays zero

An all-zero speed series yields an all-zero corrected speed (no spurious motion). _is_reverse_from_speed would raise on all-zeros, so this path is only safe with interpolate_path=False — see test_correct_trajectory_with_zero_speed.

▶ Variable frequency & future re-interpolation gen1/gen2

Underlying data may be 25 Hz (0.04 s) or 20 Hz (0.05 s). If the policy's query times don't line up with the corrected series, you must opt into allow_future_reinterpolation=True — otherwise a strict lookup (tol 0.01 s) raises RuntimeError. See test_pre_intervention_no_interp.

▶ Past data in the policy window is unsupported RuntimeError

The augmentation only models the future; negative policy time deltas raise immediately (test_pre_intervention_corrector_with_past_in_policy_raises). Past vehicle data (separate from policy) is fine and preserved (..._with_past_in_vehicle).

▶ Numerical regression lock drive_only_reference.json

For forward-only driving, outputs are pinned to a captured reference (test_drive_only_numerical_regression) — the reverse-driving logic must not perturb the original forward code path by even 1e-7.
