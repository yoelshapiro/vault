Pre-Intervention Trajectory Correction

When a safety driver disengages the autonomous vehicle, the few seconds before the takeover are gold: they show the model heading toward a mistake. This augmentation rewrites those pre-intervention labels so the model learns the expert's correction — earlier and smoother — instead of the behaviour that triggered the takeover.

1 Where the data comes from

The augmentor is a functional_datapipe("augment_vehicle_preintervention") that sits in the data pipeline and rewrites labels on the fly. It only touches real autonomous-vehicle (AV) fleet logs — frames where the car was driving itself and a human then took over.

The trigger: an intervention = automation going OFF

Every frame carries an automation_active boolean. An intervention is the index where it flips True → False — that's the safety-driver disengagement. get_intervention_offsets() finds it with np.diff(...) < 0. utils.py:38

What is filtered out

  • Novel-view-synthesis & data-collection (non-AV) frames — skipped (is_nvs, no automation_active).
  • Frames that are not pre-intervention: needs automation_active[origin] AND time_until_intervention < safeguard_clean_av_offset_sec. pre_intervention.py:129
  • Examples with 0 or >1 interventions in the window, or the intervention beyond max_pre_intervention_offset. intervention.py:177
  • Paths that aren't fully valid, or where geometry/speed direction disagree → BadPreInterventionException, sample dropped.

Key idea on the path data: path_pose is the recorded future trajectory. After the disengagement those points are what the human actually drove. So the "rejoin target" already encodes the expert outcome — the augmentation just builds a smooth, physically-consistent label that reaches it.

2 How the correction works

The heart is correct_trajectory() pre_intervention.py:257. Two things are rewritten in lock-step: the path (geometry) and the speed (timing). Then poses are re-interpolated along the new path at the new speeds.

STEP A
Distance to intervention
cumdist_from_speed integrates |speed|·dt. Read off the distance at the disengagement index.
STEP B
Pick a rejoin point
2·dist + 3 metres ahead → correction_end_index. The corrected path must merge back to the recorded (expert) path here.
STEP C
Clamp at direction change
_clamp_at_direction_change stops the clothoid ironing out a genuine stop-and-reverse cusp (parking!). Speed is zeroed at the cusp.
STEP D
Re-fit the path
correct_path(method="clothoid") fits a G1-Hermite clothoid from now → rejoin, with forward/reverse aware tangents.
STEP E
Re-shape the speed
correct_speed ramps linearly from current speed v₀ to a future speed v₂, reaching it by the intervention time + offset.
STEP F
Safety gate
validate_pre_intervention_accelerations drops the sample if a slow-down intervention is paired with a speed-up heuristic.
STEP G
Re-interpolate poses
Poses + curvature are sampled along the new path at the new cumulative distances, then written back as policy_* targets.

The speed law — correct_speed intervention.py:251

With t1 = ix + offset and t2 = 2·ix + offset:

v₀ = speed[0]  (now)
v₂ = speed[t2] (future / expert outcome)
a  = (v₂ − v₀) / t1
v[0..t1] = v₀ + a·k
v = [ ramp ‖ original speed from t2 on ]

Result: the car is told to start matching the expert's eventual speed now, rather than waiting for the human to grab the controls.

The path law — correct_path trajectory.py:72

A clothoid (curvature linear in arc-length) is fit between two boundary poses:

start = pose[0]   (θ₀)
end  = pose[correction_end] (θ₁)
Clothoid.G1Hermite(x₀,y₀,θ₀, x₁,y₁,θ₁)
reverse → θ + π, curvature negated
then continue original spacing

Result: a single smooth arc replaces the late, jerky human takeover — and it begins the manoeuvre earlier.

⚠︎ What is faithful vs. illustrative. The speed correction (correct_speed), the distance integration (cumdist_from_speed, trapezoidal on |speed|), the 2·d+3 rejoin point, the acceleration-bucket safety gate and the direction-change clamp are faithful JS ports of the Python. The clothoid path fit is approximated here by a G1 cubic-Hermite spline (matching endpoint position + heading) — visually clothoid-like; the real code uses pyclothoids.Clothoid.G1Hermite. The per-scenario raw paths/speeds are synthetic stand-ins for real fleet logs, constructed to make each disengagement legible.
