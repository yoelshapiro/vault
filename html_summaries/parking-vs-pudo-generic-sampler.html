Legacy parking vs the generic parking_pudo sampler

Two families of bucketed datasets that mine the corpus frame stream for parking maneuvers. The legacy sampler detects gear-zero segments and buckets them by gear-change count. The generic materialisation sampler (new on boris/pudo_generic_materialization) detects semantic park / PUDO / unpark / unpudo events using gear + hazard + robotaxi trip evidence, with displacement sanity-checks. This page compares event detection, windows, and bucket taxonomy.

legacy  datasets/parking/

  • Exists on main — the established parking sampler.
  • Two datasets: default (legacy gear transitions) and gc (gear-change-count).
  • PUDO appears only as an exclusion (nopudo buckets drop hazard-on stops).
  • Platforms gen2 mache + partner_mb; start date 2019-10-28.
  • No robotaxi trip table, no lat/lon displacement gating.

generic  datasets/parking_pudo/

  • New on this branch — the "generic materialisation" sampler.
  • Three datasets: default (windows), anchors (one frame), events (event table + metadata).
  • PUDO / UnPUDO are positive classes driven by hazard + robotaxi trip evidence.
  • Platforms gen2/mache (events also ipace); park ≥ 2025-08-01, PUDO ≥ 2025-12-01.
  • Self-contained: computes everything from the corpus frame stream — no notebook / pre-materialised event table.

legacy detection

Gear → segments → count

  • Gear from get_gear; Gen2 Mache reconstructs gear from speed (CAN gear unreliable) — speed sign → D/R, validated P/N ≥2 s merged, forward-filled.
  • Park segment = gear==0 run lasting ≥ min_parking_duration_sec (2.0 s).
  • Park event = segment start; unpark event = end−1 (last P frame).
  • Gear smoothed (min_gear_dwell_sec=0.5) to kill pass-through blips; shifts counted inside the window → the gc{N} label.
  • PUDO = exclusion only via exclude_pudo (hazard indicator on).
parking/filters.py · select_parking_event / select_unparking_event

generic detection

Signals → context → semantic events

  • Shared _signals: smooth gear (≥2 s), hazard context (indicator==HAZARD, dilated), trip context (robotaxi trip_events haversine-matched within 100 m to neutral stops, dilated).
  • Park segment ≥2 s, then park vs PUDO: is_pudo = any(hazard|trip over span). Park also requires the run to have no trip events.
  • Approach gating: >5 m displacement vs a 30 s lookback (or previous park anchor) — kills jitter / re-parks.
  • Departure: first moving frame after Park, verified >5 m over 60 s, capped at next stop; classified unpudo vs unpark; forward/reverse split.
  • Per-anchor AV-mode gating for DC buckets.

The core conceptual shift

Legacy asks "how many gear shifts inside this stop?" Generic asks "what kind of event is this stop, and which phase of it am I in?" — using robotaxi/hazard evidence the legacy sampler never sees.

What the generic windows add

Anchoring at the physical first-stop / first-movement frame (not the raw gear change), distance caps (10 m approach, 5 m departure), a dedicated short pre-departure window, and directional-indicator extension — none of which exist in the legacy buffers.

Bottom line

The generic sampler replaces gear-change-count bucketing with a context-aware event model: it turns PUDO from a thing-to-exclude into a labelled class, anchors windows on real motion transitions, and is fully self-contained — at the cost of more signal machinery (hazard dilation, trip joins, displacement checks).
