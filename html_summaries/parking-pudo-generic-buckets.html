Dataset summary

Parking / PUDO bucket groups

How each bucket group in the new parking_pudo generic-materialisation dataset is calculated from the raw corpus frame stream and how it is filtered. Materialised directly from wayve_corpus.all_data via services/sampling — no parking notebooks, no pre-built PUDO event table.

Overview

Every bucket is combine(exclusions, platform filter, country suffix, event filter). The event filter is the interesting part — it recomputes parking events per run from gear, speed, indicator and trip-table signals, then selects a frame window. There are five families of event filters and they are crossed with the five country suffixes to produce the final bucket set.

Shared signal pipeline

Before any bucket is selected, _signals() in signals.py normalises one run into the arrays every selector consumes. This is where parking events are actually "detected".

Timestamps & speed. timestamps_s = TIMESTAMP_UNIXUS / 1e6; speed_mps = get_speed(df); frame rate from get_frequency.
Gear smoothing. get_gear → integer gear, then _smooth_short_gear_segments replaces any gear segment shorter than min_gear_segment_sec (default 2.0s) with the previous stable gear. Park = gear 0.
Indicator cleanup. indicator_light normalised to enum IDs, then _cleanup_hazard rewrites the fast approach part of a hazard segment to a directional indicator (left/right by drive-side country GBR/JPN) and the fast departure part to OFF — so only the genuinely-stopped portion stays HAZARD.
Geofence mask. non_geofenced = ~excluded_geofence_mask(df) removes the four office geofences before any PUDO evidence counts.
Hazard evidence. real_pudo_hazard = (indicator == HAZARD) & non_geofenced, then time-dilated by ±hazard_window_sec.
Trip evidence. _trip_pudo_context: completed pickup/dropoff locations from inferred__robotaxi.trip_events matched to a gear-to-park anchor within 100m (haversine); the whole parked segment becomes synthetic hazard context, dilated and masked by non_geofenced.
PUDO context. pudo_hazard = real_pudo_hazard | pudo_trip. Selectors pick the source with context_source ∈ {all, hazard, trip} (all = union). A frame is "PUDO" if this mask is true, "parking" if false.

Park segments & the parking window

_parking_segments keeps Park (gear 0) runs whose smoothed duration ≥ min_parking_duration_sec (default 2.0s). For each such segment the approach-to-stop window (_parking_window) is:

  • start = earlier of "30m before stop" (cumulative distance) and "12s before stop" (time);
  • extended back to a nearby directional-indicator onset (−3s) if that indicator is within 30m of the park anchor;
  • end = 1s after the gear-to-park frame;
  • intersected with |speed| > 0.01 dilated ±2s, so only the moving-nearby part is kept.

A segment is classified park vs PUDO by the PUDO-context value at the frame just before Park starts (_park_context_index = park_start − 1).

① Park / PUDO event buckets

dc_park · dc_pudo · dc_pudo_trip PARK

How it's calculated

select_park_pudo_event builds signals, finds valid park segments, and for each computes the approach-to-stop window. Windows are assigned greedily so earlier segments claim frames first (unassigned_window = window & ~assigned). A segment is emitted into the bucket when its PUDO-context value at park_start − 1 matches the requested event_type:

is_pudo = pudo_context[park_start - 1]
if (event_type == "pudo") == is_pudo:
    mask |= unassigned_window      # window bucket
    # or mask[start] = window.any()  (anchor_only)

How it's filtered

  • Context: dc_park = non-PUDO; dc_pudo = PUDO with ctx=all (hazard ∪ trip); dc_pudo_trip = debug overlap, ctx=trip only.
  • Params: min_parking_duration_sec=2.0, min_gear_segment_sec=2.0, hazard_window_sec=10.0.
  • Exclusions: PARKING_PUDO_EVENT_EXCLUSIONS = DC base (no intervention-label filter) + exclude_autonomous (DC = driver-controlled frames only).

② Unpark / UnPUDO buckets

dc_unpark · dc_unpudo · dc_unpudo_trip DEPART

How it's calculated

_departure_events walks every valid park segment, finds the first frame with |speed| > 0.01 after the segment ends (the movement anchor, not crossing into the next park segment), and classifies it as UnPUDO if the PUDO context is true anywhere across the parked + pre-movement interval (park_start−1 … max(end, anchor)+1). select_unpark_unpudo_event then selects anchor → anchor + 10s.

How it's filtered

  • Context: dc_unpark = parked interval not PUDO; dc_unpudo = parked interval is PUDO (ctx=all); dc_unpudo_trip = debug, ctx=trip.
  • Params: movement_speed_threshold_mps=0.01, after_movement_sec=10.0; same min-duration / smoothing defaults.
  • Exclusions: PARKING_PUDO_EVENT_EXCLUSIONS (DC base + exclude_autonomous).

③ Pre-departure buckets

dc_pre_unpark · dc_pre_unpudo · dc_pre_unpudo_trip DEPART

How it's calculated

Same movement anchors and same UnPUDO classification as group ②, but select_pre_departure_event selects the 0.9s immediately before the anchor: mask[searchsorted(t, t[anchor] − 0.9) : anchor] = True.

How it's filtered

  • Context: identical unpark/UnPUDO split to group ②; _trip is the debug overlap.
  • Params: before_movement_sec=0.9.
  • Exclusions: PARKING_PUDO_EVENT_EXCLUSIONS.

④ Gear-change buckets

dc_parking_gear_change · dc_pudo_gear_change GEAR

How it's calculated

select_gear_change_event takes every smoothed gear transition (diff(gear) != 0) and selects a small window before_sec=0 → after_sec=0.5s around frames whose context matches.

How it's filtered

  • Context: dc_parking_gear_change = non-PUDO at the gear-change frame; dc_pudo_gear_change = PUDO, with a wider hazard_window_sec=30.0 so the cleaned hazard reaches the gear change.
  • Exclusions: PARKING_PUDO_EVENT_EXCLUSIONS.

⑤ Pre-CA buckets

pre_ca_parking · pre_ca_pudo · pre_ca_unpark · pre_ca_unpudo PRE-CA

How it's calculated

Interventions are AV→DC transitions: auto[:-1]==1 & auto[1:]==0. The pre-CA window is the 1.2s before each qualifying intervention frame.

Gear-change variant (select_intervention_near_gear_change): keep interventions within ±30s of a smoothed gear change whose context matches (parking / pudo, PUDO uses hazard_window=30s).
Departure variant (select_intervention_near_departure_event): keep interventions within ±30s of a matching unpark/UnPUDO movement anchor.

How it's filtered

  • Remain-stopped guard: drop handovers where the vehicle is stopped (|speed| ≤ 0.01) at the intervention and still stopped 1s later.
  • Exclusions: PARKING_PUDO_PRE_CA_EXCLUSIONS = full base set without exclude_autonomous — pre-CA frames are expected to still be AV before handover.

⑥ CA short / long buckets

ca_parking_* · ca_pudo_* · ca_unpark_* · ca_unpudo_* CA

How it's calculated

Same intervention selectors as pre-CA, but with window="post". The post window keeps only frames that are driver-controlled after the handover (mask = auto == 0 inside the window):

  • short: post_intervention_start=0 → CA_SHORT_WINDOW = 1.48s
  • long: CA_SHORT_WINDOW + 0.04 = 1.52s → CA_LONG_WINDOW = 5.0s

How it's filtered

  • Context / proximity: identical to the matching pre-CA bucket (gear-change ±30s, or departure-anchor ±30s; same context split).
  • Remain-stopped guard: same as pre-CA.
  • Exclusions: PARKING_PUDO_CA_EXCLUSIONS = full base set + exclude_autonomous (post-CA frames are DC).

⑦ Failed-to CA buckets

pre_ca_failed_to_* · ca_failed_to_*_short · ca_failed_to_*_long FAILED-TO

How it's calculated

select_failed_to_intervention selects intervention frames directly by the inferred__intervention__what label ∈ {failed_to_park, failed_to_pudo, failed_to_unpark, failed_to_unpudo}. Same pre (1.2s) / post (short 1.48s, long 5.0s) windows.

How it's filtered

  • No gear / departure proximity check — the label alone qualifies the intervention.
  • Remain-stopped guard still applies (rejects stopped-and-stays-stopped handovers).
  • Hazard context is not used (hazard_window_sec=0.0); gear is only smoothed to keep the shared signal derivation consistent.
  • Exclusions: pre-CA → PRE_CA set; short/long → CA set.

Out-of-scope intervention handling

diversion, lens_obscured and uncategorised are kept (allow-listed) for parity with the event notebook; all other out-of-scope whats stay excluded — but only on CA / pre-CA buckets. DC buckets do not filter on inferred__intervention__what at all (event-table comparison mode).

Deliberately disabled (kept for a future stricter variant)

select_allowed_run_tags, exclude_low_steering_bias_confidence, exclude_mache_without_wheel_odometery, exclude_diversion_and_lens_obscured_interventions. Also not applied: stopped-segment, first/last-index, run-level autonomous masks.

Temporary: the event-notebook-only geofence list and the relaxed DC inferred__intervention__what filtering are comparison choices for notebook parity. Both should be revisited before this becomes the production parking/PUDO materialisation policy.

PUDO context & geofences

What counts as PUDO

PUDO context is the union of two evidence sources, both masked to exclude office geofences:

  • Hazard — cleaned hazard-light frames (approach/departure rewritten away), time-dilated.
  • Trip — completed pickup/dropoff locations from inferred__robotaxi.trip_events (event_type = TRIP_EVENT_TASK_COMPLETED, pickup/dropoff waypoints) matched to a gear-to-park anchor within 100m. The raw indicator column is never modified — the synthetic hazard lives only in the derived mask. Trip rows are aggregated to one row per run (list columns) before the join so corpus frames can't be duplicated.

The *_trip_* buckets isolate only the trip-table contribution for debugging.

Office geofences ignored for classification

london_office, sunnyvale_office, germany_leonberg, yokohama_office — matching EXCLUDE_GEOFENCE_KEYS in the PUDO/UnPUDO event-detection notebook. Hazard/trip evidence inside these is dropped before the park/PUDO split (in signals.py), and the same names are also used as a run exclusion in the base set.

Country suffixes

Each event filter is crossed with uk, usa, deu, jpn, global from COUNTRIES_FILTERS.
