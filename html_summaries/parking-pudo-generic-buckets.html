Parking / PUDO bucket groups

How each bucket group in the parking_pudo generic-materialisation dataset is calculated from the raw corpus frame stream and how it is filtered. Materialised directly from wayve_corpus.all_data via services/sampling — no parking notebooks, no pre-built PUDO event table.

datasets parking_pudo · _parking · _pudo · _anchors binary driving 3.0.68 platform Gen2 Mache (+ Alpha3 / Alpha3-Lidar) dates 2025-12-01 → 2026-06-07 suffixes uk · usa · deu · jpn · global

Overview

Every bucket is combine(exclusions, platform filter, country suffix, event filter). The event filter is the interesting part — it recomputes parking events per run from gear, speed, indicator and trip-table signals, then selects a frame window. Five families of event filters are crossed with the five country suffixes, and the exclusion set is chosen per-bucket by whether the bucket is a strict park/unpark bucket or a relaxed PUDO/UnPUDO bucket.

Shared signal pipeline

Before any bucket is selected, _signals() in signals.py normalises one run into the arrays every selector consumes. This is where parking events are actually "detected". Two scalar knobs are threaded through: min_gear_segment_sec (gear smoothing, default 2.0s) and hazard_window_sec (hazard/trip dilation, default 10s, 30s for the PUDO gear-change & CA buckets).

Timestamps, speed, distance. timestamps_s = TIMESTAMP_UNIXUS / 1e6; speed_mps = get_speed(df); cumulative_distances_m = get_cumdist(df); frame rate from get_frequency.
Gear smoothing. get_gear → integer gear, then _smooth_short_gear_segments replaces any gear segment shorter than min_gear_segment_sec with the previous stable gear (only when that segment isn't the first in the run). Park = gear 0.
Indicator → enum. indicator_light is normalised to enum IDs via indicator_to_enum. (No hazard cleanup / drive-side rewrite — that step was removed.)
Hazard evidence. pudo_hazard_context = (indicator == HAZARD), time-dilated by ±hazard_window_sec. No geofence masking here.
Trip evidence. _trip_pudo_context: for each Park (gear 0) segment, the frame just before Park (start − 1) is matched by haversine to the nearest trip-event location; if within 100m the whole [start−1, end) interval is marked, then dilated ±hazard_window_sec. Trip events include completed pickup/dropoff and task-started rows. No geofence masking here.
PUDO context. _pudo_context returns hazard | trip for context_source="all" (or just one source for "hazard" / "trip"). A frame is "PUDO" if this mask is true, "parking" if false.

Park segments & the parking window

_parking_segments keeps Park (gear 0) runs whose smoothed duration ≥ min_parking_duration_sec (default 2.0s). For each such segment the approach-to-stop window (_parking_window) is:

  • dist_start = "30m before stop" (cumulative distance), time_start = "12s before stop"; the window starts at the later (max) of the two;
  • _directional_indicator_start may move the start back to a left/right indicator onset (−3s) found within indicator_lookback_sec = 30s before the park anchor — but never earlier than the 30m distance cap;
  • end = 1s after the gear-to-park frame;
  • intersected with |speed| > 0.01 dilated ±2s, so only the moving-nearby part is kept.

A segment is classified park vs PUDO by the PUDO-context value at the frame just before Park starts (_park_context_index = max(park_start − 1, 0)).

Event displacement gates added by the fix commits

Two checks suppress duplicate anchors around the same physical stop:

  • Approach (_has_pre_park_approach_displacement, select_park_pudo_event): the gear-to-park anchor is dropped unless the car moved > 5m point-to-point from its position approach_lookback_sec = 30s earlier. If a previous valid park anchor lies inside that window, the check starts from that anchor instead.
  • Departure (_has_post_departure_displacement, departure selectors): the first-movement anchor is dropped unless the car reaches > 5m from the gear-change point within departure_lookahead_sec = 60s, clipped at the next valid park anchor.

① Park / PUDO event buckets

dc_park · dc_pudo · dc_pudo_trip PARK

How it's calculated

select_park_pudo_event builds signals, finds valid park segments, and for each that passes the approach-displacement gate (> 5m over a 30s lookback) computes the approach-to-stop window. Windows are assigned greedily so earlier segments claim frames first (unassigned_window = window & ~assigned). A segment is emitted when its PUDO-context value at park_start − 1 matches the requested event_type:

if not _has_pre_park_approach_displacement(...):  # > 5m in last 30s
    continue
window = _parking_window(signals, start)
unassigned_window = window & ~assigned
assigned |= window
is_pudo = pudo_context[_park_context_index(start)]
if (event_type == "pudo") == is_pudo:
    mask |= unassigned_window                      # window bucket
    # or mask[start] = unassigned_window.any()     # anchor_only

How it's filtered

  • Context: dc_park = non-PUDO; dc_pudo = PUDO with ctx=all (hazard ∪ trip); dc_pudo_trip = debug overlap, ctx=trip only.
  • Params: min_parking_duration_sec=2.0, min_gear_segment_sec=2.0, hazard_window_sec=10.0, approach_lookback_sec=30.0, min_approach_displacement_m=5.0.
  • Exclusions: dc_park → strict PARK_UNPARK_EVENT; dc_pudo/dc_pudo_trip → relaxed PARKING_PUDO_EVENT (= DC base + exclude_autonomous).

② Unpark / UnPUDO buckets

dc_unpark · dc_unpudo · dc_unpudo_trip DEPART

How it's calculated

_departure_events walks every valid park segment and, via _departure_anchor, finds the first frame with |speed| > 0.01 at/after the gear-leaves-park frame — but only if _has_post_departure_displacement confirms the car reaches > 5m from the gear-change point within 60s (clipped at the next park segment). It classifies the event as UnPUDO if the PUDO context is true anywhere across [park_start−1 … max(end, anchor)+1). select_unpark_unpudo_event then selects anchor → anchor + 10s.

How it's filtered

  • Context: dc_unpark = parked interval not PUDO; dc_unpudo = parked interval is PUDO (ctx=all); dc_unpudo_trip = debug, ctx=trip.
  • Params: movement_speed_threshold_mps=0.01, after_movement_sec=10.0, departure_lookahead_sec=60.0, min_departure_displacement_m=5.0; same min-duration / smoothing defaults.
  • Exclusions: dc_unpark → strict PARK_UNPARK_EVENT; dc_unpudo/_trip → relaxed PARKING_PUDO_EVENT.

③ Pre-departure buckets

dc_pre_unpark · dc_pre_unpudo · dc_pre_unpudo_trip DEPART

How it's calculated

Same movement anchors and same UnPUDO classification as group ② (including the 5m/60s departure gate), but select_pre_departure_event selects the 0.9s immediately before the anchor: mask[searchsorted(t, t[anchor] − 0.9) : anchor] = True.

How it's filtered

  • Context: identical unpark/UnPUDO split to group ②; _trip is the debug overlap.
  • Params: before_movement_sec=0.9.
  • Exclusions: dc_pre_unpark → strict PARK_UNPARK_EVENT; dc_pre_unpudo/_trip → relaxed PARKING_PUDO_EVENT.

④ Gear-change buckets

dc_parking_gear_change · dc_pudo_gear_change GEAR

How it's calculated

select_gear_change_event takes every smoothed gear transition (diff(gear) != 0) and selects a small window before_sec=0 → after_sec=0.5s around frames whose context matches.

How it's filtered

  • Context: dc_parking_gear_change = non-PUDO at the gear-change frame; dc_pudo_gear_change = PUDO, with a wider hazard_window_sec=30.0 so the dilated hazard reaches the gear change.
  • Exclusions: dc_parking_gear_change → strict PARK_UNPARK_EVENT; dc_pudo_gear_change → relaxed PARKING_PUDO_EVENT.

⑤ Pre-CA buckets

pre_ca_parking · pre_ca_pudo · pre_ca_unpark · pre_ca_unpudo PRE-CA

How it's calculated

Interventions are AV→DC transitions: auto[:-1]==1 & auto[1:]==0. The pre-CA window is the 1.2s before each qualifying intervention frame.

Gear-change variant (select_intervention_near_gear_change): keep interventions within ±30s (gear_window_sec) of a smoothed gear change whose context matches (parking / pudo; PUDO uses hazard_window=30s).
Departure variant (select_intervention_near_departure_event): keep interventions within ±30s (departure_window_sec) of a matching unpark/UnPUDO movement anchor (which itself passed the 5m/60s departure gate).

How it's filtered

  • Remain-stopped guard: drop handovers where the vehicle is stopped (|speed| ≤ 0.01) at the intervention and still stopped 1s later (also dropped if there is no frame 1s later).
  • Exclusions: pre_ca_parking/pre_ca_unpark → strict PARK_UNPARK_PRE_CA (full base + exclude_out_of_scope_intervention, no exclude_autonomous); pre_ca_pudo/pre_ca_unpudo → relaxed PARKING_PUDO_PRE_CA (base only, no exclude_autonomous). Pre-CA frames are expected to still be AV before handover.

⑥ CA short / long buckets

ca_parking_* · ca_pudo_* · ca_unpark_* · ca_unpudo_* CA

How it's calculated

Same intervention selectors as pre-CA, but with window="post". The post window keeps only frames that are driver-controlled after the handover (mask = auto == 0 inside the window):

  • short: post_intervention_start=0 → CA_SHORT_WINDOW = 1.48s
  • long: CA_SHORT_WINDOW + 0.04 = 1.52s → CA_LONG_WINDOW = 5.0s

How it's filtered

  • Context / proximity: identical to the matching pre-CA bucket (gear-change ±30s, or departure-anchor ±30s; same context split).
  • Remain-stopped guard: same as pre-CA.
  • Exclusions: ca_parking_*/ca_unpark_* → strict PARK_UNPARK_CA; ca_pudo_*/ca_unpudo_* → relaxed PARKING_PUDO_CA. Both add exclude_autonomous (post-CA frames are DC).

⑦ Failed-to CA buckets

pre_ca_failed_to_* · ca_failed_to_*_short · ca_failed_to_*_long FAILED-TO

How it's calculated

select_failed_to_intervention selects intervention frames directly by the inferred__intervention__what label ∈ {failed_to_park, failed_to_pudo, failed_to_unpark, failed_to_unpudo} (an unsupported label raises ValueError). Same pre (1.2s) / post (short 1.48s, long 5.0s) windows.

How it's filtered

  • No gear / departure proximity check — the label alone qualifies the intervention.
  • Remain-stopped guard still applies (rejects stopped-and-stays-stopped handovers).
  • Hazard context is not used (hazard_window_sec=0.0); gear is only smoothed to keep the shared signal derivation consistent.
  • Exclusions: routed like the others — *_failed_to_park/*_failed_to_unpark → strict PARK_UNPARK_*; *_failed_to_pudo/*_failed_to_unpudo → relaxed PARKING_PUDO_* (pre-CA set for pre_ca_*, CA set for *_short/*_long).

Restored data-quality filters fix commit

exclude_low_steering_bias_confidence and exclude_mache_without_wheel_odometery are now applied to both families (the earlier draft listed them as deliberately disabled — they were restored by “restore parking pudo geofence quality filters”).

Out-of-scope intervention handling

Relaxed family: diversion, lens_obscured and uncategorised are kept (allow-listed via PARKING_PUDO_ALLOWED_OUT_OF_SCOPE_INTERVENTION_WHATS); all other out-of-scope whats stay excluded on CA / pre-CA, and DC event buckets do not filter on inferred__intervention__what at all. Strict family applies the full exclude_out_of_scope_intervention on pre-CA and exclude_diversion_and_lens_obscured_interventions.

Disabled only for the relaxed family (PARKING_PUDO_DISABLED_DATA_QUALITY_EXCLUSIONS)

select_allowed_run_tags, exclude_runs_that_are_too_short, exclude_diversion_and_lens_obscured_interventions — kept available for a stricter future variant but not applied to the Zak-parity PUDO buckets (they are applied to the strict park/unpark family).

Anchor-safe exclusions

Anchor-only buckets run through _anchor_safe_exclusions, which strips exclude_stopped_segments so a gear-to-park or intervention anchor that happens to be stopped at that exact frame still survives (“keep stopped frames in parking pudo anchors”).

PUDO context & geofences

What counts as PUDO

PUDO context is the union of two evidence sources (no geofence masking applied at this stage):

  • Hazard — frames where the enum indicator equals HAZARD, time-dilated ±hazard_window_sec. There is no longer any approach/departure hazard rewrite.
  • Trip — locations from inferred__robotaxi.trip_events where event_type = TRIP_EVENT_TASK_COMPLETED with a pickup/dropoff waypoint, or event_type = TRIP_EVENT_TASK_STARTED — matched to a gear-to-park context frame within 100m (haversine). Trip rows are deduped by (trip_id, event_kind, rounded lat/lon) and aggregated to one row per run (list columns) before the join, so corpus frames can't be duplicated. The raw indicator column is never modified — the synthetic hazard lives only in the derived mask.

The *_trip_* buckets isolate only the trip-table contribution for debugging.

Geofences — applied at the exclusion layer, not in classification

PUDO/UnPUDO classification uses hazard and trip evidence wherever it appears in the run. Geofencing is now done by the ordinary run/sample filter exclude_geofenced (in every base set) over the full sampling list EXCLUDE_GEOFENCES: DE_BEAUVOIR_TOWN, LONDON_OFFICE, SOMERS_TOWN, YOKOHAMA_OFFICE, SUNNYVALE_OFFICE, MOUNTAIN_VIEW_OFFICE, TOKYO_PRINCE_HOTEL_A/B, TOKYO_TRC_OFFICE + TEST_TRACK_GEOFENCES.

Heads-up: signals.excluded_geofence_mask still exists but is now unused (dead code) — the old in-signal office-geofence mask was removed. The earlier draft’s “Geofence mask” pipeline step and real_pudo_hazard & non_geofenced no longer reflect the code.

Country suffixes

Each event filter is crossed with uk, usa, deu, jpn, global from COUNTRIES_FILTERS.
